# Feature 025 — Frontend OpenAPI Codegen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Angular frontend consumes API payload TYPES generated from the backend OpenAPI spec, so backend and frontend share one contract and response-shape drift becomes a TypeScript compile error.

**Architecture:** Backend Swashbuckle spec is enriched (nullability/required + XML docs), exported offline to a checked-in `swagger.json` via the Swashbuckle CLI, and ng-openapi-gen (models-only consumption) generates payload DTO interfaces into `src/app/core/api/generated/`. The same `swagger.json` also produces a committed, offline, human-browsable HTML API reference (`docs/api-reference/index.html`, Redoc). Hand-written generic wrappers (`ApiResponse<T>`, `PagedResultDto<T>`), UI-only unions, request-param interfaces, the 13 HttpClient services, facades, and interceptors all stay unchanged. Migration is incremental per feature via type re-exports, so downstream imports and specs never move.

**Tech Stack:** .NET 10 / Swashbuckle.AspNetCore 10.2.3 + Swashbuckle.AspNetCore.Cli 10.2.3 (new tool manifest); Angular 20.3 / TS ~5.9 strict / Vitest; ng-openapi-gen + @redocly/cli (npm dev-deps, pinned exact).

**Branch:** `feature-024-contracts-index-cleanup` (feature 025 developed on this branch per user decision). **Feature number 025 confirmed** (docs/ max is 024; specs/ max is 019; no collision).

## Locked decisions (do not reopen during execution)

1. Tool: **ng-openapi-gen, models-only consumption** — generated services are never imported.
2. Backend spec enrichment is **mandatory**: `SupportNonNullableReferenceTypes()` + `NonNullableReferenceTypesAsRequired()`, XML docs for the 6 undocumented controllers and the undocumented response DTOs. `[ProducesResponseType]` for 400/404/500 is **out of scope** (follow-up, see §Non-goals).
3. Spec source: checked-in `swagger.json` produced offline via `dotnet swagger tofile` (tool manifest + CLI pinned 10.2.3). No running server needed.
4. Generated output is **committed** (Vercel build has no dotnet).
5. Migration: **incremental** — system → roots → remaining words explorers → mushaf.
6. Staleness guard: regen + `git diff --exit-code` script; convention now, CI job later.
7. Locations: generated models `Frontend/quran-dashboard-ui/src/app/core/api/generated/`; spec checked in at `**Frontend/quran-dashboard-ui/openapi/swagger.json**` (proposed here: lives next to its consumer, is present in the Vercel checkout, and keeps `docs/contracts/` a thin pointer index).
8. Onboarding API reference: static, offline, human-browsable HTML generated from the SAME `swagger.json` via `@redocly/cli` (`redocly build-docs`), committed at `**docs/api-reference/index.html**`. Generated, never hand-edited; regenerated by the staleness guard. Opens in a browser without running the backend. (Enabling Swagger UI beyond Development stays optional/secondary — not part of this feature.)

## Scope

**In scope**

- Backend: `QuranDashboard.Api` Swagger options, XML docs on 6 controllers + 35 response DTO files, `QuranDashboard.Application.Abstractions.csproj` doc-file generation, new `Backend/.config/dotnet-tools.json`, two new scripts in `Backend/scripts/`.
- Frontend: ng-openapi-gen dev-dep + config + npm script, generated folder, new shared `paged-result.model.ts`, DTO-subset swap in the 8 feature/core model files; `@redocly/cli` dev-dep + `docs:api` npm script.
- Docs: static generated API reference at `docs/api-reference/index.html`; README updates listed in §Docs updates; this plan document.

**Non-goals (explicit)**

- NO client/service generation consumption — the 13 hand-written HttpClient services stay byte-identical.
- NO facade, store, interceptor, or `app.config.ts` changes.
- NO `[ProducesResponseType]` / typed 400/404/500 schemas (deferred follow-up; record in Controllers/README as such).
- NO runtime behavior change anywhere — this feature is types + spec + docs only.
- NO change to `ApiResponse<T>` (backend record or frontend mirror), no envelope unwrapping.
- NO CI workflow creation (`.github/workflows` does not exist; guard stays a script).
- NO EF migrations, no DB access, no import pipelines.

## Risks, rollback, stop conditions


| Risk                                                                                                                   | Mitigation                                                                                                                                                                                                                                                                                                         |
| ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| NRT options reshape more of the spec than expected (e.g. collection properties, envelope `data` nullability surprises) | Phase 1 verification asserts specific schemas; diff the whole `swagger.json` on first export and read it before Phase 2. **Stop** if the emitted spec contradicts actual runtime shapes (e.g. `data` marked required although 400 responses omit it — expected: `Data` is `T?` so it stays nullable; assert this). |

| `swagger tofile` fails at host build (config/connection-string)                                                        | CLI uses `AddSwaggerGen` services, not the dev-only middleware; CORS/DbContext options resolve lazily so no throw is expected.
