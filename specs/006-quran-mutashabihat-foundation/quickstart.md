# Quickstart — Quran Mutashabihat Foundation

How to stage the local source files, create the schema, run the mutashabihat import, and verify the
result. Prerequisite: the **Feature 002 import has already run** (PostgreSQL holds `quran_ayahs` with a
unique `verse_key` per ayah).

> Commands are illustrative; run them from the Backend solution root unless noted. The import is
> **source-driven** — it reads two local JSON files and joins `quran_ayahs`.

## 1. Stage the local source package (local-only; not committed)

The staged package already exists at the **local, in-repo** path (beside `quran-foundation/` and
`quran-morphology/`). `resources/` is Git-ignored, so these data files stay **local-only** — "copy" means
a local file copy, **not** `git add`/commit/push.

```text
App/resources/import-sources/mutashabihat/
  manifest.json
  README.md
  mutashabihat-ul-quran/phrases.json
  similar-ayahs/matching-ayah.json
```

`manifest.json` carries, per file: `role`, `path`, `originPath`, `expectedRecordCount`, `fileSizeBytes`,
`sha256`, `notes`. The importer verifies these before the run (exact file set, size, `sha256`) and
re-verifies size/`sha256` after assembly, before commit (`MUT-SOURCE-UNCHANGED`). The original
`resources/mutashabihat/` working folder is **read-only provenance only** and is never read at runtime.
`phrase_verses.json` is intentionally **not** staged (it is a derivable reverse index; see plan.md /
research R10).

## 2. Create the schema (one-time, schema-only migration)

Per `Backend/CLAUDE.md`, migrations are generated by EF tooling **on explicit request** and contain
**schema only** (no `HasData` — there is no controlled vocabulary to seed). After adding the three
entities + EF configurations + `DbSet`s:

```bash
# generate (name illustrative) — review the generated migration before applying
dotnet ef migrations add AddQuranMutashabihat \
  --project infrastructure/QuranDashboard.Infrastructure \
  --startup-project api/QuranDashboard.Api

# apply when ready (only on explicit request)
dotnet ef database update \
  --project infrastructure/QuranDashboard.Infrastructure \
  --startup-project api/QuranDashboard.Api
```

The migration creates exactly: `quran_mutashabihat_groups`, `quran_mutashabihat_occurrences`,
`quran_similar_ayah_links` (all empty), with their unique constraints, the `source_ayah_id <>
target_ayah_id` check, the `occurrences.group_id` ON DELETE CASCADE, and the read indexes
(`occurrences(ayah_id)`, `links(target_ayah_id)`).

## 3. Run the import

```bash
# first import (targets empty) — default source = App/resources/import-sources/mutashabihat/
dotnet run --project tools/QuranDashboard.DataImporter -- import-mutashabihat

# explicit source / custom report directory
dotnet run --project tools/QuranDashboard.DataImporter -- import-mutashabihat \
  --source App/resources/import-sources/mutashabihat --report-out ./reports

# re-import after a prior run (targets non-empty) — must force
dotnet run --project tools/QuranDashboard.DataImporter -- import-mutashabihat --force
```

Behavior:
- Verifies the manifest/source files first; refuses early on any file-set/size/`sha256` mismatch.
- Refuses if `quran_ayahs` is missing/empty (run `import-foundation` first).
- Refuses if any of the three tables is non-empty and `--force` is absent (nothing changes; prints a
  console message and writes no report artifact).
- `--force` truncates **only** the three mutashabihat tables, then rebuilds in one transaction.
- Never touches `quran_ayahs` / `quran_words` (or any prior feature's table) and never writes the source
  files.
- Resolves every `verse_key → ayah_id`, recomputes group counters, collapses the 1 duplicate occurrence,
  flags the representative occurrence, stores `coverage` raw, and stores directed links faithfully (no
  reverse rows).
- Validates before commit; on any hard-check failure it rolls back (writes nothing).
- Writes a Markdown + JSON report on every import attempt (success or failure). When `--report-out` is
  omitted the report goes to **`resources/report/mutashabihat/`** (relative to the repository root).

## 4. Verify

Read the report (verdict `PASS`, totals, all hard checks ✅, the known warnings) and/or spot-check the DB:

```sql
-- 814 groups; 3,557 stored unique occurrences; 3,552 directed links
SELECT count(*) FROM quran_mutashabihat_groups;          -- 814
SELECT count(*) FROM quran_mutashabihat_occurrences;     -- 3557
SELECT count(*) FROM quran_similar_ayah_links;           -- 3552
SELECT count(DISTINCT source_ayah_id) FROM quran_similar_ayah_links; -- 1162

-- every reference resolves: 0 dangling ayah FKs (FKs already enforce this)
SELECT count(*) FROM quran_mutashabihat_occurrences o
  LEFT JOIN quran_ayahs a ON a.id = o.ayah_id WHERE a.id IS NULL;    -- 0
SELECT count(*) FROM quran_similar_ayah_links l
  LEFT JOIN quran_ayahs a ON a.id = l.target_ayah_id WHERE a.id IS NULL; -- 0

-- no single-ayah groups; no self-links
SELECT count(*) FROM quran_mutashabihat_groups WHERE distinct_ayah_count < 2; -- 0
SELECT count(*) FROM quran_similar_ayah_links WHERE source_ayah_id = target_ayah_id; -- 0

-- recomputed counters match the actual occurrence rows
SELECT count(*) FROM quran_mutashabihat_groups g
  WHERE g.occurrence_count <>
        (SELECT count(*) FROM quran_mutashabihat_occurrences o WHERE o.group_id = g.id); -- 0

-- coverage stored raw: the 4 rows > 100 are retained (0 clamped)
SELECT count(*) FROM quran_similar_ayah_links WHERE coverage > 100;   -- 4

-- at most one representative occurrence per group; group 1782 has zero
SELECT count(*) FROM (
  SELECT group_id FROM quran_mutashabihat_occurrences
  WHERE is_representative GROUP BY group_id HAVING count(*) > 1) t;    -- 0

-- read recipes the downstream feature will use (no extra tables):
-- all groups of an ayah:
SELECT g.* FROM quran_mutashabihat_occurrences o
  JOIN quran_mutashabihat_groups g ON g.id = o.group_id WHERE o.ayah_id = :id;
-- all occurrences of a group:
SELECT * FROM quran_mutashabihat_occurrences WHERE group_id = :id;
-- similar ayahs of an ayah (outgoing) and incoming (undirected view, no reverse rows):
SELECT * FROM quran_similar_ayah_links WHERE source_ayah_id = :id;
SELECT * FROM quran_similar_ayah_links WHERE target_ayah_id = :id;

-- source untouched
SELECT count(*) FROM quran_ayahs;                        -- unchanged
```

## 5. Run the tests

```bash
dotnet test tests/QuranDashboard.Tests
```

Integration tests use Testcontainers PostgreSQL (`postgres:16-alpine`) with **synthetic, source-safe**
tiny groups/links (never real verse passages) to prove ayah resolution, counter recompute, representative
flagging (incl. the `source.key`-absent group kept with zero representative occurrences), occurrence
dedupe, directed-link fidelity, coverage-stored-raw, refusal/`--force`, atomic rollback on a hard-check
failure, and that `quran_ayahs` **and** the source files are unchanged. Reader/assembler unit tests run
without a DB.

## What this feature does NOT do

No API, no UI, no read model, no reverse/undirected similar-ayah rows, no clamped/normalized coverage, no
`phrase_verses` table, no merged/polymorphic ayah-relations table, no `import_runs` history table, no
tafsir/translation/audio, no treating any stored value as Mushaf text, no reading of the original
`resources/mutashabihat/` working folder at runtime, and no modification of `quran_ayahs`, `quran_words`,
or any prior feature's table.
