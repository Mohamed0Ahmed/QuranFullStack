# Quickstart: Quran Navigation Metadata Foundation

Operator-only backend import. Adds juz/hizb/rub/sajda navigation metadata and tags every ayah with its
juz/hizb/rub. No UI/API. Run from the repository root.

## Prerequisites

- .NET 10 SDK; PostgreSQL reachable via the Infrastructure connection string.
- Feature 002 already imported (`quran_ayahs` populated with the 6,236 ayahs). If empty, run
  `import-foundation` first — the navigation import refuses with `AyahsMissing` otherwise.
- The additive migration for the four nav tables + three `quran_ayahs` columns has been generated by EF
  tooling and applied (see "Migration", below).
- The staged package present at `resources/import-sources/quran-navigation-metadata/` (package root with
  `manifest.json` + `sources/`). `resources/` is Git-ignored; in CI the real-data run is skipped.

## Run the import

```bash
# Default source (package root) and default report dir:
dotnet run --project Backend/tools/QuranDashboard.DataImporter -- import-navigation-metadata

# Explicit source root and report dir:
dotnet run --project Backend/tools/QuranDashboard.DataImporter -- \
  import-navigation-metadata \
  --source resources/import-sources/quran-navigation-metadata \
  --report-out Backend/report/feature-009-quran-navigation-metadata-foundation

# Re-run after data already exists (atomic reload of navigation-owned data only):
dotnet run --project Backend/tools/QuranDashboard.DataImporter -- import-navigation-metadata --force
```

Expected success console summary:

```text
juz=30, hizb=60, rub=240, sajda=15, ayahsTagged=6236, warnings=0
Report written to: .../Backend/report/feature-009-quran-navigation-metadata-foundation
```

A second run **without** `--force` exits non-zero and changes nothing (`NAV-RERUN-GUARD`).

## Verify

```sql
SELECT count(*) FROM quran_juzs;    -- 30
SELECT count(*) FROM quran_hizbs;   -- 60
SELECT count(*) FROM quran_rubs;    -- 240
SELECT count(*) FROM quran_sajdas;  -- 15

-- every ayah tagged (expect 0):
SELECT count(*) FROM quran_ayahs
WHERE juz_number IS NULL OR hizb_number IS NULL OR rub_number IS NULL;

-- ayah -> division lookup (example):
SELECT verse_key, juz_number, hizb_number, rub_number FROM quran_ayahs WHERE verse_key = '2:255';

-- sajda list with type (expect 15; 11 optional / 4 required):
SELECT sajdah_number, verse_key, sajdah_type FROM quran_sajdas ORDER BY sajdah_number;

-- ayah text untouched: compare a known value before/after — must be unchanged.
SELECT verse_key, left(text_uthmani, 12) FROM quran_ayahs WHERE verse_key = '1:1';
```

Open the JSON + Markdown reports in the report directory; confirm `verdict = accepted`, `persisted = true`,
`ayahCoverage.complete = true`, and the "No Quran ayah text was read or stored" statement.

## Migration (generate only; apply on explicit request)

```bash
# Generated by EF tooling later, only when implementation/migration is explicitly requested.
# Canonical wrapper (run from the Backend root) — uses the API as the startup project per convention:
cd Backend && ./scripts/add-mig AddQuranNavigationMetadata
# Equivalent explicit command (from the Backend root):
#   dotnet ef migrations add AddQuranNavigationMetadata \
#     --project infrastructure/QuranDashboard.Infrastructure \
#     --startup-project api/QuranDashboard.Api \
#     --context QuranDashboardDbContext --output-dir Migrations
# Do NOT hand-write migration/snapshot files. Do NOT run `database update` without explicit request.
```

The migration is additive: four new tables + three nullable `quran_ayahs` columns. No existing column or
data is altered; `text_uthmani` is untouched.

## Tests

```bash
dotnet test Backend/tests/QuranDashboard.Tests --filter FullyQualifiedName~Quran.Navigation
```

Coverage: manifest/package validation, `verse_mapping` assembler (expansion + coverage + hierarchy),
validation failures (gaps/overlaps/unresolved keys/invalid sajda type), integration on synthetic
`quran_ayahs`, rerun-refusal + `--force` reload, forced-reload rollback, report shape, and the
no-Quran-text safety assertion. The real-package end-to-end test is gated on the package being present.

## Safety reminders

- Reads only the staged package root; never edits source files.
- References ayahs by `verse_key`; never reads or stores Quran ayah text.
- Touches only the four nav tables + the three `quran_ayahs` nav columns. Everything else is read-only.
