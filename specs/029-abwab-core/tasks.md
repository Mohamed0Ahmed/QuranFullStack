## How to use this file (read before starting — this is the contract for the implementer)

1. **Reuse the accepted `028` substrate — do NOT rebuild it.** The following already exist and are
   accepted; every `029` writer plugs into them:
   - Tracked `ChangeSet` unit of work + `SavingChanges` guard (rejects no-ChangeSet writes and
     physical deletes; enforces soft-delete) — `Backend/infrastructure/QuranDashboard.Infrastructure/Abwab/Persistence/`.
   - `AbwabWriteBarrier` singleton + `AbwabRevisionState` singleton (`AuditHeadSequence`,
     `TimelineGeneration`, **`TreeRevision`**, `Version`/xmin) — `.../Abwab/Timeline/`, `.../Abwab/Concurrency/`.
   - `ExpectedTimelineGeneration` command/read contract + exact-409-before-mutation guard.
   - Server clock (`IServerClock`); append-only audit engine; `@angular/forms` (installed by the
     `028` permission-administration form — **reuse it, do not re-install**); the §14.1 frontend
     primitives (cache/store/action/conflict, IndexedDB) in `src/app/core/`; the Playwright harness
     in `e2e/harness/`.
2. **Every backend mutation** runs in **one audited `ChangeSet`** and carries
   `ExpectedTimelineGeneration` + expected `xmin` + expected `TreeRevision` (where structural), and
   passes the barrier. Bump `TreeRevision` **exactly once** per atomic structural operation.
3. **Real infrastructure**: backend correctness tests run against **real PostgreSQL** via the
   existing Testcontainers fixture `Backend/tests/QuranDashboard.Tests/Abwab/_Fixtures/PostgresFixture.cs`
   (xUnit collection `AbwabDbCollection`). UI tests run in a **real browser** (Playwright).
4. **EF migrations are generated by EF tooling only** (never hand-written), per `Backend/CLAUDE.md`.
   After generating one, report its migration name + files.
5. **Exact `abwab.*` 409 codes only** (from §11 / `contracts/`). Never invent, rename, or remap a
   code. The codes this feature uses:
   `abwab.section_name_conflict`, `abwab.section_not_empty`, `abwab.permanent_default_section`,
   `abwab.category_name_conflict`, `abwab.category_alias_conflict`, `abwab.category_cycle`,
   `abwab.category_overlapping_move`, `abwab.category_unavailable`,
   `abwab.category_reserved_by_pending`, `abwab.manual_protection`,
   `abwab.manual_protection_scope_conflict`, `abwab.ordinary_protection`,
   `abwab.stabilization_active`, `abwab.tree_revision_stale`, `abwab.timeline_generation_stale`,
   `abwab.row_stale`.
6. **Hard invariants** (fail the task if violated): **NO drag-and-drop** anywhere; **NO Quran
   foreign key** — `RepresentativeQuranExcerpt` is a plain string, not ayah-validated;
   **composite-read redaction is a backend DTO projection**, never frontend hiding; the
   **ManualProtection adapter is accepted BEFORE any protected writer** (US2 before US3).
7. **Ground truth** for each task is the matching file under `contracts/` + `data-model.md`
   (both cite the Master Plan §-anchors). Read the referenced contract before coding a task.

## Dependencies & Execution Order

### Mandatory stage order (§18.3)

```
Setup (P1) → Foundational (P2) → US1 → US2 → US3 → US4 → Polish
```

- **US1 (schema/read)** — first. No mutation surface exists at its checkpoint.
- **US2 (protection storage/resolver)** — after US1 (protection attaches to categories). Its
  ManualProtection adapter MUST be **accepted before US3** (order gate).
- **US3 (writers)** — after US1 **and** US2 (writers consult the resolver and need the accepted
  adapter). Contains the bulk of the domain behavior.
- **US4 (frontend slice)** — last; drives the US3 writers/reads; reuses the `028` frontend
  substrate and `@angular/forms`.

### Within each story

- Tests are written **first** and must fail before implementation.
- Domain entities → EF config → migration (EF tooling) → ports → application handlers → API → UI.
- EF migrations (T020, T032) are generated by tooling **after** their entity types + configs exist.

### Parallel opportunities

- **[P] within a story** = different files, no incomplete dependency: e.g. the domain entities
  T016–T018; the US1 test suite T009–T015; the US3 test suite T036–T049; the US4 tests T063–T066.
- **Across stories**: constrained by the mandatory order. The only genuine cross-stack parallel is
  building US4 frontend scaffolding (T067 mock, T069 cache) against the frozen contracts while US3
  backend finishes — but US4 acceptance still follows US3.
- **Not parallel**: US2 blocks US3 (adapter order gate); US3 handlers T052–T060 largely touch
  overlapping category surfaces and should be sequenced within the story.

## Implementation Strategy

### MVP scope

The MVP is **US1 + US2 + US3** (all P1): the category schema/read model, the protection
storage/resolver, and the tracked writers with all three restore adapters accepted for `033`. That
is the backend domain vertical slice §18.3 requires. **US4 (P2)** then adds the frontend vertical
slice for end-to-end usability and the §6.3 audit renders.

> **US4 is NOT optional.** MVP here is an internal *partial-delivery milestone*, not §18.3
> completion. The feature exit **requires US4** — composite-read UI parity, the §6.3 audit render
> payloads, and the no-drag/RTL/large-tree browser suite are §18.3 acceptance criteria (SC-015,
> SC-016). The feature is done only when **all four** stages pass in CI.

### Incremental delivery

1. Setup + Foundational → normalizer + shared corpus + no-Quran-FK guard.
2. US1 → schema + read model + Section/Category adapters (order verified as a facet) (no mutation surface).
3. US2 → protection storage + resolver; ManualProtection adapter accepted (order gate).
4. US3 → all writers, manual protection, exact codes, three adapters accepted for `033`.
5. US4 → frontend slice (mock/HTTP parity, tree/search/editor/protection UI, §6.3 renders, no-drag).
6. Polish → quickstart validation, READMEs, guards, report, handoff to `030`/`031`.

### Exit

Complete only when **every** §18.3 exit/acceptance criterion passes in CI, in the mandatory order;
all three adapters (Section, Category, ManualProtection) are accepted for `033` (Order verified as a facet); and `029` built
nothing owned by `027`–`028` or `030`–`034` (no Quran FK, no relationship/template/attribution/
workspace/audit-restore/realtime surface).
