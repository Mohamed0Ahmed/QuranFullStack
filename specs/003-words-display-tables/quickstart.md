# Quickstart — Quran Words Display Tables Foundation

How to create the schema, rebuild the four derived tables from the existing database, and
verify the result. Prerequisite: the **Feature 002 import has already run** (PostgreSQL
holds 83,668 `quran_words`, of which 77,432 are readable).

> Commands are illustrative; run them from the Backend solution root unless noted. The
> rebuild reads the DB — it needs **no** source files.

## 1. Create the schema (one-time, schema-only migration)

Per `Backend/CLAUDE.md`, migrations are generated by EF tooling **on explicit request**
and contain **schema only** (no `HasData`). After adding the four entities + EF
configurations + `DbSet`s:

```bash
# generate (name illustrative) — review the generated migration before applying
dotnet ef migrations add WordsDisplayTables \
  --project infrastructure/QuranDashboard.Infrastructure \
  --startup-project api/QuranDashboard.Api

# apply when ready (only on explicit request)
dotnet ef database update \
  --project infrastructure/QuranDashboard.Infrastructure \
  --startup-project api/QuranDashboard.Api
```

The migration creates exactly: `quran_words_ordered_tashkeel`,
`quran_words_ordered_simple`, `quran_words_unique_tashkeel`, `quran_words_unique_simple`
(empty).

## 2. Rebuild the tables

```bash
# first build (targets empty) — no --force needed
dotnet run --project tools/QuranDashboard.DataImporter -- rebuild-words

# rebuild after a prior run (targets non-empty) — must force
dotnet run --project tools/QuranDashboard.DataImporter -- rebuild-words --force

# custom report directory
dotnet run --project tools/QuranDashboard.DataImporter -- rebuild-words --force --report-out ./reports
```

Behavior:
- Refuses if any of the four tables is non-empty and `--force` is absent (nothing changes;
  a refusal prints a console message and writes no report artifact).
- `--force` truncates **only** the four derived tables, then rebuilds in one transaction.
- Never touches `quran_words` / `quran_ayahs` / `quran_surahs`.
- Validates before commit; on any hard-check failure it rolls back (writes nothing).
- Writes a Markdown + JSON report on every rebuild attempt (success or failure). When
  `--report-out` is omitted the report goes to **`resources/report/words-display/`**
  (relative to the repository root).

> **Importer note:** the importer is now invoked with an explicit verb —
> `... -- import-foundation --source <path> [--force]` (previously `--source` was passed
> without a verb).

## 3. Verify

Read the report (verdict `PASS`, per-table totals, all hard checks ✅) and/or spot-check
the DB:

```sql
-- 77,432 each, no markers
SELECT count(*) FROM quran_words_ordered_tashkeel;   -- 77432
SELECT count(*) FROM quran_words_ordered_simple;     -- 77432

-- contiguous mushaf order
SELECT min(word_order_in_mushaf), max(word_order_in_mushaf),
       count(DISTINCT word_order_in_mushaf)
FROM quran_words_ordered_tashkeel;                   -- 1, 77432, 77432

-- derived unique counts (reported, not hardcoded)
SELECT count(*) FROM quran_words_unique_tashkeel;    -- ~21,210 (informational)
SELECT count(*) FROM quran_words_unique_simple;      -- ~14,783 (informational)

-- occurrences sum equals readable words
SELECT sum(occurrences_count) FROM quran_words_unique_tashkeel;  -- 77432

-- first occurrence = earliest mushaf order (sample)
SELECT u.text_uthmani, u.first_word_order_in_mushaf
FROM quran_words_unique_tashkeel u
ORDER BY u.first_word_order_in_mushaf
LIMIT 5;

-- source tables untouched
SELECT count(*) FROM quran_words;                    -- 83668
```

## 4. Run the tests

```bash
dotnet test tests/QuranDashboard.Tests
```

Integration tests use Testcontainers PostgreSQL (`postgres:16-alpine`) with **synthetic,
source-safe** word fixtures (never real Quran text) to prove ordering, statistics,
tashkeel-vs-simple grouping, first-occurrence selection, refusal/`--force`, atomic
rollback on validation failure, and that source tables are unchanged.

## What this feature does NOT do

No API, no UI, no search (no search columns/indexes/normalization; `text_imlaei_simple` is
stored only as a passive reference), no morphology/roots/lemma/POS/i3rab, no
tafsir/translations/audio/mutashabihat, no new external source files, and no modification
of the Feature 002 tables.
